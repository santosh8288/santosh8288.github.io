RAP Architecture

Learn RAP as a complete business-object model

SAP's RESTful Application Programming Model becomes much easier to understand when it is treated as an end-to-end business application architecture rather than a collection of individual ABAP features.

The central idea is simple: model a business object, define what it can do, implement the business rules, expose the object as a service and consume it through a suitable client.

01 · Model

CDS entities define the business data model, relationships, compositions, associations, keys and projections.

02 · Behavior

Behavior definitions describe what the business object can do: create, update, delete, actions, validations and determinations.

03 · Transaction

RAP controls transactional processing through EML, locking, draft handling, save processing and transactional messages.

04 · Expose

Service definitions and bindings expose the business object through OData for Fiori Elements and other consumers.

Architecture

The RAP Architecture Layers

Data Model

CDS view entities represent business data and define relationships between business objects.

Typical topics:

CDS · Associations · Compositions · Keys · Projections

Behavior Layer

The behavior definition describes the allowed transactional operations and business rules.

Typical topics:

CRUD · Actions · Validations · Determinations

Transaction Layer

RAP manages transactional interaction through the business-object contract.

Typical topics:

EML · Draft · Locking · Save Sequence · Messages

Service Layer

The business object becomes consumable through service definitions and service bindings.

Typical topics:

OData · Service Definition · Service Binding

UI Layer

Fiori Elements can consume the exposed RAP service and generate much of the application experience from metadata and annotations.

Security & Quality

Production applications also require authorization, testing, performance analysis, extensibility and clean-core considerations.

Learning Path

Recommended RAP Learning Sequence

Stage Question Topics
1. Model What is the business object? CDS, keys, compositions, associations, projections
2. Behavior What can it do? CRUD, actions, determinations, validations
3. Transaction How are changes processed? EML, locking, draft, save processing
4. Security Who can perform the operation? Authorization, feature control
5. Service How is it consumed? Service definition, binding, OData
6. UI How does the user interact? Fiori Elements, annotations, side effects
7. Quality Can it scale and remain maintainable? Testing, performance, clean core

Solution Architecture

Questions an SAP Solution Architect Should Ask

Business Object

What is the real business object? What is its lifecycle? Which entities belong to it?

Transaction Boundary

Which changes must be committed together? Where should the transaction begin and end?

Behavior

Is this operation CRUD, an action, a determination or a validation?

Authorization

Who can see the object? Who can modify it? Who can approve it?

Integration

Should the solution use RAP, released APIs, events, workflow or another integration mechanism?

Clean Core

Is the extension using released APIs and extension points rather than modifying SAP standard?
