Behavior Implementation

Where custom RAP business logic is implemented and how to keep it maintainable.

When implementation is needed

RAP provides framework behavior, but real applications usually contain business-specific rules. Those rules are implemented in behavior pools and local handler/saver classes according to the scenario.

Validation example

A travel validation might read BeginDate and EndDate, detect an invalid range, add the affected key to failed and report a meaningful business message.

Good habits

Keep handlers focused. Avoid mixing unrelated database access, UI concerns, integration calls and business rules in one large method.

Architect’s perspective

Framework-managed behavior should remain framework-managed whenever possible. Custom code should express business rules, not rebuild the framework.
