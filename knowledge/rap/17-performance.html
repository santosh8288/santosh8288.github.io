Performance is end-to-end

Performance can be influenced by the data model, database operations, behavior implementation, service payload and UI consumption.

Key practices

Select only required fields; avoid repeated reads; design relationships deliberately; keep service payloads focused; avoid expensive logic in frequently triggered determinations; measure before optimizing.

Diagnostic sequence

Slow UI → inspect network/service payload → inspect OData request → inspect RAP behavior → inspect CDS/database access → measure the bottleneck.

Architect’s perspective

Optimize what you can measure. Avoid premature micro-optimizations that make business logic harder to maintain.
