Stock Transfer — Transaction & Validation

A stock-transfer request shows how a transactional business object can validate source/destination and quantity before allowing a transfer operation.

Case studiesAll scenarios01 · Purchase Order Approval02 · Travel Management — Draft to Active03 · Supplier Invoice — Validation & Determination04 · Sales Order — Action & Status Control05 · Employee Onboarding — Authorization & Feature Control06 · Plant Maintenance Request — EML07 · Stock Transfer — Transaction & Validation08 · Customer Credit Review — Approval & Authorization09 · Project Expense Claim — Draft + Validation + Approval
Scenario: transfer 10 units of a material from Plant A to Plant B. Validate positive quantity, source/destination difference and required material data. The final posting should be treated as a business operation, not a raw table update.

Action

action postTransfer result [1] $self;

Validation logic

IF Quantity <= 0. → reject transaction IF SourcePlant = DestinationPlant. → reject transaction IF Material is initial. → reject transaction

Architectural consideration

In a real S/4HANA implementation, inventory posting should use the supported released business APIs/objects for the target release rather than inventing a parallel stock ledger. RAP can orchestrate the request and expose the user-facing transaction boundary.

Production note: The code is intentionally a teaching/reference skeleton. CDS entity names, database fields, message classes, authorization implementation, released APIs and syntax can vary by ABAP platform/SAP S/4HANA release. Activate and test against your target system before treating it as production code.
