Purchase Order Approval

A realistic RAP scenario for a purchase order that moves through Submit → Pending Approval → Approved/Rejected. This case intentionally separates the RAP business object from the enterprise workflow engine.

Case studiesAll scenarios01 · Purchase Order Approval02 · Travel Management — Draft to Active03 · Supplier Invoice — Validation & Determination04 · Sales Order — Action & Status Control05 · Employee Onboarding — Authorization & Feature Control06 · Plant Maintenance Request — EML07 · Stock Transfer — Transaction & Validation08 · Customer Credit Review — Approval & Authorization09 · Project Expense Claim — Draft + Validation + Approval
Purchase Order approval is a strong example because it combines actions, validations, authorization, feature control, status transitions and integration/workflow concerns. In a real S/4HANA solution, approval may be implemented with SAP Flexible Workflow; RAP should expose a clean business object and business operations rather than reinventing the workflow engine.
Business rule: a draft PO can be submitted only when mandatory data is complete. A submitted PO becomes Pending Approval. An authorized approver can Approve or Reject. Rejection requires a reason. A rejected PO can be resubmitted after correction.
Important architecture boundary: the sample below demonstrates the RAP business-object side. Behavior definition

managed implementation in class zbp_i_purchaseorder unique;
strict ( 2 );

define behavior for ZI_PurchaseOrder alias PurchaseOrder
persistent table zpo_header
lock master
authorization master ( instance )
etag master LastChangedAt
{
  create;
  update;
  delete;

  action submit result [1] $self;
  action approve result [1] $self;
  action reject parameter ZD_PoReject result [1] $self;

  validation validateAmount on save { create; update; }
  validation validateSubmit on save { create; update; }

  field ( readonly ) PurchaseOrderUUID, PurchaseOrder,
                         Status, CreatedBy, CreatedAt, LastChangedAt;

  mapping for zpo_header {
    PurchaseOrderUUID = po_uuid;
    PurchaseOrder     = po_number;
    Supplier          = supplier_id;
    CompanyCode       = company_code;
    TotalAmount       = total_amount;
    Currency          = currency_code;
    Status            = status;
    ApprovalNote      = approval_note;
    CreatedBy         = created_by;
    CreatedAt         = created_at;
    LastChangedAt     = last_changed_at;
  }
}

Action implementation

METHOD submit.

  READ ENTITIES OF zi_purchaseorder IN LOCAL MODE
    ENTITY PurchaseOrder
    FIELDS ( Status Supplier CompanyCode TotalAmount )
    WITH CORRESPONDING #( keys )
    RESULT DATA(orders).

  LOOP AT orders ASSIGNING FIELD-SYMBOL().

    IF -Status <> 'DRAFT'.
      APPEND VALUE #( %tky = -%tky ) TO failed-purchaseorder.
      APPEND VALUE #(
        %tky = -%tky
        %msg = new_message_with_text(
                 severity = if_abap_behv_message=>severity-error
                 text     = 'Only draft purchase orders can be submitted' )
      ) TO reported-purchaseorder.
      CONTINUE.
    ENDIF.

    MODIFY ENTITIES OF zi_purchaseorder IN LOCAL MODE
      ENTITY PurchaseOrder
      UPDATE FIELDS ( Status )
      WITH VALUE #( ( %tky = -%tky Status = 'PENDING' ) )
      FAILED DATA(update_failed)
      REPORTED DATA(update_reported).

  ENDLOOP.

ENDMETHOD.

Approve / reject logic

METHOD approve.

  READ ENTITIES OF zi_purchaseorder IN LOCAL MODE
    ENTITY PurchaseOrder
    FIELDS ( Status )
    WITH CORRESPONDING #( keys )
    RESULT DATA(orders).

  LOOP AT orders ASSIGNING FIELD-SYMBOL().
    IF -Status <> 'PENDING'.
      APPEND VALUE #( %tky = -%tky ) TO failed-purchaseorder.
      CONTINUE.
    ENDIF.

    MODIFY ENTITIES OF zi_purchaseorder IN LOCAL MODE
      ENTITY PurchaseOrder
      UPDATE FIELDS ( Status )
      WITH VALUE #( ( %tky = -%tky Status = 'APPROVED' ) ).
  ENDLOOP.

ENDMETHOD.

Validation

METHOD validateAmount.

  READ ENTITIES OF zi_purchaseorder IN LOCAL MODE
    ENTITY PurchaseOrder
    FIELDS ( TotalAmount Currency )
    WITH CORRESPONDING #( keys )
    RESULT DATA(orders).

  LOOP AT orders ASSIGNING FIELD-SYMBOL().
    IF -TotalAmount <= 0.
      APPEND VALUE #( %tky = -%tky ) TO failed-purchaseorder.
      APPEND VALUE #(
        %tky = -%tky
        %msg = new_message_with_text(
          severity = if_abap_behv_message=>severity-error
          text = 'Purchase order amount must be greater than zero' )
      ) TO reported-purchaseorder.
    ENDIF.
  ENDLOOP.

ENDMETHOD.
