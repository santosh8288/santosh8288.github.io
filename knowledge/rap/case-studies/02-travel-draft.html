Travel Management — Draft to Active

A travel-request business object is ideal for demonstrating managed draft. The employee can enter dates, destination and cost, leave the application, return later, and finally activate the request.

RAP draft handling is managed by the RAP transactional engine. Enabling `with draft` makes the business object draft-aware; the runtime persists intermediate transactional state, while the application focuses on business logic. SAP's own RAP documentation uses a Travel business object as a draft example. citeturn0search0turn0search2

CDS root

@EndUserText.label: 'Travel Request'
define root view entity ZI_TravelRequest
  as select from ztravel_request
  composition [0..*] of ZI_TravelExpense as _Expense
{
  key travel_uuid       as TravelUUID,
      travel_id         as TravelID,
      employee_id       as Employee,
      destination       as Destination,
      begin_date        as BeginDate,
      end_date          as EndDate,
      purpose           as Purpose,
      total_estimated   as TotalEstimated,
      currency_code     as Currency,
      overall_status    as OverallStatus,
      local_last_changed_at as LastChangedAt,

      _Expense
}

Managed draft behavior

managed implementation in class zbp_i_travel unique;
strict ( 2 );
with draft;

define behavior for ZI_TravelRequest alias Travel
persistent table ztravel_request
draft table ztravel_request_d
lock master
total etag LastChangedAt
authorization master ( instance )
{
  create;
  update;
  delete;

  association _Expense { create; with draft; }

  validation validateDates on save { create; update; }
  determination calculateTotal on modify { field ExpenseAmount; }

  draft determine action Prepare
  {
    validation validateDates;
  }

  field ( readonly ) TravelUUID, TravelID, OverallStatus, LastChangedAt;
}

Draft lifecycle

User creates Travel Request ↓ RAP creates draft instance ↓ User edits destination/dates/expenses ↓ Determinations + validations ↓ Prepare ↓ Activate ↓ Active Travel Request

Implementation note

For draft-enabled behavior, use `%tky` when referring to transactional instances. SAP documents that the draft indicator `%is_draft` becomes part of the transactional key in draft scenarios, which helps implementations address draft and active instances correctly. citeturn0search4
